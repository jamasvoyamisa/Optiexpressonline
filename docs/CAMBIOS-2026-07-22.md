## 6. Arreglos de bugs detectados hoy

### 6.1 Migración Alembic con ID duplicado
- La migración de bloqueo de login usó por error un `revision` que ya existía (`d4e5f6a7b8c9`).
- Eso rompía el grafo de Alembic (ciclo) y, al declarar columnas nuevas en el modelo sin aplicarlas en BD, **RH/Admin no podían listar empleados** (error de columna desconocida).
- **Corregido:** revisión única `f1a2b3c4d5e6`, aplicada en producción.

### 6.2 Portal de checadas — mensajes de error
- Al endurecer el login del portal se empezó a devolver HTTP 401/429.
- El HTML del portal solo lee `mensaje` / `ok`, no el status → el usuario veía un error genérico.
- **Corregido:** se vuelve a responder 200 con `ok=false` y mensaje claro; el conteo de fallos/bloqueo sigue activo por detrás.

### 6.3 Módulo RH (Edith) — listas vacías, admin sí veía datos
**Causa:** `PersonalPage` carga todo con `Promise.all` e incluye `/asistencia/devices` (solo admin).  
Si RH recibe **403** en devices, falla toda la carga y empleados/empresas quedan vacíos aunque esas APIs respondan 200.

**Corregido:** devices solo se pide si es admin; si falla, no tumba el resto del listado.  
Commit: `a0729fa`.
