## 1. Vacaciones / horario — no labora sábados (caso Marco TI)

### Contexto
- Empleado: **Marco Antonio Díaz de León** (id 65, No. 134, Gerente TI).
- Horario activo: **General** (09:00–18:00 L–V) con `hora_salida_sabado = 14:00`.
- En Personal tenía desmarcado «¿Trabaja los sábados?» (`horario_sabado_id = NULL`).
- Aun así el proceso diario generaba **FALTA** los sábados («No se presentó (sin checadas)»).
- Agosto: faltas sábado **1** y **8** (sin justificar). En julio las de sábado ya estaban justificadas.

### Causa
El checkbox de Personal solo limpiaba `empleados.horario_sabado_id`.  
El generador de incidencias **seguía heredando** `horarios.hora_salida_sabado` del L–V (General → 14:00), así que lo trataba como que sí labora sábado.

La UI decía «No se generarán incidencias los sábados», pero el backend no lo respetaba.

### Solución
- Override en `empleado_horario.hora_salida_sabado`:
  - `""` = no labora sábado (gana sobre el horario base).
  - `NULL` = heredar del L–V (p. ej. tiendas con General y sábado).
  - hora (p. ej. `14:00`) = salida sábado propia.
- Al guardar en Personal con sábado **desmarcado** → se escribe `""`.
- Al **marcar** sábado de nuevo → se limpia el `""` (vuelve a heredar / usar `horario_sabado_id`).
- Misma prioridad en: proceso diario de faltas, resolver de checadas y conteo de checadas requeridas.
- Datos Marco: asignación `empleado_horario` id 248 con override `""`.
- Se eliminaron las 2 faltas sábado automáticas no justificadas de agosto (1 y 8).

### Archivos
- `backend/app/modules/asistencia/service.py`
- `backend/app/modules/asistencia/checada_especial_resolver.py`
- `backend/app/modules/personal/service.py`

### Cómo verificar
| Qué | Dónde |
|-----|--------|
| Sin falta sábado futuro | Proceso diario / incidencias de Marco los sábados |
| Checkbox | Personal → editar empleado → desmarcar sábado → guardar → no deben generarse faltas sábado aunque el horario base tenga salida sábado |
| Otros con General + sábado | Empleados **sin** override `""` siguen laborando sábado como antes |

## 4. Vacaciones — PDF firmado (plantilla vs archivo)

**Qué hace:** tras la aprobación del jefe (`aprobada_jefe` o `aprobada`), el empleado, el jefe o RH pueden **subir el PDF escaneado/firmado**. Si ya hay PDF firmado, la UI **oculta** la plantilla HTML generada y solo muestra «Ver PDF firmado» (+ Reemplazar).

**Reglas:**
- Formato solo **PDF** (máx. 10 MB).
- Disco: `/opt/optiexpress/storage/vacaciones/firmados/{empleado_id}/{solicitud_id}.pdf` (`VACACIONES_FIRMADOS_DIR`).
- BD: metadatos en `solicitudes_vacaciones` (`documento_firmado_*`); migración `h3i4j5k6l7m8`.
- **Apagado por defecto:** Admin debe activarlo en Configuración → Eventos especiales → Vacaciones generales («Subida de PDF firmado»). Flag `sistema_flags.vacaciones_pdf_firmado` (migración `i4j5k6l7m8n9`).

**API:**
- `POST /vacaciones/solicitudes/{id}/documento-firmado` (multipart `archivo`)
- `GET /vacaciones/solicitudes/{id}/documento-firmado`

**UI:** Mis Vacaciones, RH → Solicitudes de vacaciones, Mi Área → Vacaciones (filtro «Todas» / «Aprobadas por jefe»).

**Archivos clave:** `vacaciones/service.py`, `routes.py`, `AccionesDocumentoVacaciones.tsx`, `MisVacacionesPage.tsx`, `VacacionesPage.tsx`, `MiAreaPage.tsx`.

**Verificar:** solicitud aprobada → Subir PDF firmado → desaparece «Ver documento» plantilla → solo PDF. Ctrl+F5.
